Findings

High

Several games simulate real entity positions but render only counts or placeholders.

src/games/star-courier/StarCourierLogic.ts:60-72, 90-116; src/games/star-courier/StarCourierScene.ts:28-33; src/games/lane-rush/LaneRushLogic.ts:55-63, 79-85; src/games/lane-rush/LaneRushScene.ts:27-30; src/games/circuit-stack/CircuitStackScene.ts:26-27

Impact: Star Courier tracks projectile/enemy x-y positions and collision state, Lane Rush tracks traffic lane/y/scored state, and Circuit Stack tracks piece cells. The scenes do not expose or draw those actual positions. Players see aggregate/projected graphics that can diverge from collision truth, so these modes are technically running but not fully readable or fair as games.

Recommendation: Expose render-safe entity arrays or richer snapshots from each logic module, then draw live projectiles, enemies, traffic cars, and the full active falling piece. Add a Playwright or logic-render contract test that checks rendered objects correspond to snapshot state.

Medium

High-score persistence exists as a helper but is not wired into gameplay.

src/core/ScoreManager.ts:3-42; repo search shows no imports of ScoreManager outside its own file

Impact: The README architecture says ScoreManager and Storage handle high-score persistence, and the helper does implement localStorage-backed high scores. Current games maintain private score fields and never instantiate ScoreManager, so users will not actually keep high scores between sessions.

Recommendation: Either integrate ScoreManager into BaseGameScene or each logic engine, or revise the docs until the feature is connected. Add tests for high-score save/read behavior with a localStorage mock.

Medium

Audio unlock listeners can accumulate when switching scenes before the first user gesture.

src/games/BaseGameScene.ts:15, 30-45; src/core/AudioEngine.ts:8-24

Impact: Each scene owns an AudioEngine and calls attachUnlockListeners during create. BaseGameScene removes semantic input and restart listeners on shutdown, but AudioEngine has no teardown API for its pre-unlock pointer/key/touch listeners. Repeated game switching before an unlock can leave multiple pending global listeners.

Recommendation: Return a cleanup function from attachUnlockListeners or add an AudioEngine.detachUnlockListeners method and call it in the scene shutdown handler. A singleton shared audio service would also fit the app shell.

Low

Browser smoke tests prove load and switching, but not visual correctness or per-game interaction depth.

tests/smoke.spec.ts:26-76

Impact: The E2E suite confirms the shell loads, Neon Serpent responds, selectors work, and mobile controls are visible. It would not catch the under-rendered Star Courier, Lane Rush, or Circuit Stack states because it only asserts canvas visibility when switching games.

Recommendation: Add one interaction smoke test per game that asserts meaningful state changes through window.__ARCADE__, and consider canvas screenshot or pixel checks for hazards/projectiles/pieces once render snapshots are exposed.

Low

Production bundle is functional but large for a small arcade shell.

npm run build output; README Current Limitations

Impact: The single JS chunk is over Vite/Rolldown warning thresholds because Phaser and all scenes ship together. This is acceptable for an MVP but can slow first load on mobile networks.

Recommendation: Split game scenes with dynamic imports or tune bundling once the MVP behavior stabilizes.

What The Current Code Can Do

The app currently delivers a responsive, zero-external-asset browser arcade shell with five selectable Phaser games. It uses procedural graphics, synthesized WebAudio cues after a user gesture, keyboard and virtual touch controls, deterministic TypeScript logic engines, and test bridge snapshots for browser tests.

AreaCurrent capability
Application shellCreates a three-panel desktop layout and compact mobile layout; starts Neon Serpent by default; lets users switch among five games; exposes a restart button and mobile game picker.
InputMaps arrow/WASD keys, Space/Enter action, Escape/P pause, and touch D-pad buttons into semantic arcade input events.
RenderingUses Phaser Canvas with pixel-art settings, responsive resize scaling, and procedural Graphics primitives. No image, font, audio, or sprite-sheet downloads are required.
AudioSynthesizes select, score, hit, and game-over cues with WebAudio oscillators after unlock.

PersistenceSafeStorage and ScoreManager can persist numeric high scores to localStorage, but the running games do not currently use them.

Strengths

  • Clear separation between pure game logic and Phaser scene rendering. This makes unit tests fast and readable.
  • Good validation discipline for an MVP: build, unit tests, lint, custom architecture guard, formatting, and browser smoke tests all exist and pass.
  • The app is honest about zero assets and uses procedural drawing/audio throughout.
  • Responsive shell covers desktop and mobile interaction paths, with viewport-specific Playwright coverage.
  • Deterministic seeded randomness gives the games repeatable behavior for testing and debugging.

Suggested Next Steps

  • Make snapshots/render contracts richer for Star Courier, Lane Rush, and Circuit Stack, then draw the actual live entities.
  • Wire ScoreManager into the scoring path or remove the claim until persistence is user-visible.
  • Add AudioEngine teardown or move audio to an app-level singleton.
  • Expand E2E to exercise every game, not just switching and Neon Serpent movement.
  • Consider scene-level code splitting after gameplay fidelity is improved.
